# Flick Music Final（v3.0.0）

基于用户上传的 `Flick_Music_V2_3.zip` 升级。保留原有私人曲库、多设备配对、双指左右滑动发送、单指左滑删除、Motion Control 多选甩歌、Mac/Windows Shift+触控板校准和四类自定义事件提示音。

## 运行

需要 Node.js 22+；在解压后的项目目录：

```bash
npm ci
npm start
```

Mac/Windows 浏览器本机访问 `http://localhost:3000`，同一局域网手机访问 `http://<电脑局域网 IP>:3000`。

Motion Control 要求手机通过**受信任的 HTTPS** 页面使用；请阅读 [`README_MOTION_HTTPS.md`](README_MOTION_HTTPS.md)。没有 HTTPS 的情况下，可在高级功能使用「模拟甩动」，它发送的仍是真实的音乐文件引用，但由按钮代替传感器。

**重要：升级前先停止旧项目并备份完整的 `storage/` 目录**。新压缩包不包含用户数据库、用户音频文件或 HTTPS 私钥。如果要保留曲库，请将 V2.3 的整个 `storage/` 目录复制到 Final 项目，或者复用原来的 `FLICK_STORAGE_DIR`。不要在两个服务器同时使用同一个 SQLite 文件。数据库 schema v3 与上个版本兼容，本版本没有修改所有权数据表。

## 关键行为：必须主动允许接收

1. 两台设备完成配对时只是**建立连接**，并不自动授权文件投递。
2. 想接收歌曲的那台设备必须亲自点击 **「启用音频接收」**，等待显示「允许接收 ✓」。
3. A→B 必须 B 已开启；B→A 必须 A 已开启。如果要双向接力，两台设备都要分别点击。
4. 若未启用，服务器在 `transfer:request` 阶段直接拒绝，B 的私人曲库不会创建待接收记录。`transfer:stored` 阶段还会再次验证。
5. 刷新或 Socket 重新注册后，接收许可按当前连接**重新置为未启用**；需要再次点击。旧页面/其他标签页不能替当前标签页伪造许可。
6. 即便接收已启用，浏览器仍可能阻止远程事件自动播放；歌曲保存成功与播放接力成功始终是两种独立状态。没有接收到真实播放成功 ACK 时发送方不会错误暂停。

## 简洁音乐列表

- 上传多首文件：使用上方「上传音乐」。
- 每条卡片默认**只有音乐图标、单行文件名、播放/暂停图标按钮、右下角三个竖点**。
- 文件名太长会被裁剪，**鼠标悬停/键盘聚焦**时自动向左缓缓滚动；不会破坏手机滑动操作。
- 点击三个竖点，展开**音频格式和时长**；再次点击收起。
- **手机**：单指左滑某一首歌曲→删除确认；双指左右滑卡片→发送当前歌曲。
- **Mac/Win**：Shift+触控板左右滑卡片、按住鼠标水平拖动卡片、聚焦卡片后 Shift+←/→，均为发送。触控板自然滚动方向不匹配时进入「高级功能→触控板方向校准」。
- 点击「多选管理」仍可批量删除。Motion 多选与批量删除互相隔离。

## 极简 / 高级播放器

音乐列表下方播放器的**右上角**有一个小按钮：

- 「高级模式 ↗」：切换到黑胶唱片机视图，右上角开关可切回「极简模式 ↙」。
- **极简模式**：原生 HTML5 Audio 进度、音量、播放暂停操作，兼容原 V2.3。
- **高级模式**：黑色唱片+唱片机唱臂，中心使用用户提供的奶龙图片、由 CSS 裁成圆形。唱片随**歌曲实际播放状态**缓慢旋转；暂停时停转。
- 下方显示歌曲名、艺术家、播放进度（可拖动跳转）、当前时间/总时长，以及上一首、播放/暂停、下一首图标按钮。
- 高级/极简切换**复用同一个 Audio 元素**，不会重复播放或重新开启一条流；播放器模式会记住在当前浏览器中的选择。
- 对 MP3 读取已拥有音频的 ID3v2 歌曲名/艺术家信息（仅针对自己的授权 stream 使用小范围字节请求）。未提供标签时尝试解析「艺术家 - 歌曲名.mp3」命名方式；仍不可确定时显示**「未知艺术家」**，不会伪造作者。WAV 等无 ID3 的文件也使用文件名回退。

## Motion Control 流光修复

之前光圈问题由旋转整张 `::before` 伪元素造成，长方形线条旋出了卡片并穿越页面。

Final 版使用**纯白色、位置固定的卡片边框**，由明暗脉冲和背景高光的位置变化制造流动感。**边框本体不旋转**，其它歌曲区域不会产生跨屏轨迹。

- 选中歌曲后显示环绕卡片的纯白流光。
- 单次甩动把所选曲目顺序排入待发送队列；当前待交付歌曲立即停止光效并进入发送中状态。
- 每首必须得到对方曲库保存成功 ACK 后，发送卡片才会不规则甩出、播放丢弃音效；B 显示回收/归位动画和对应音效。
- 失败项目不播放成功动画，保留选中供重试。Motion Control 沿用 V2.3 的灵敏度、方向校准、HTTPS 和模拟模式。

## 界面整理与高级功能

- 主页面隐藏 Debug Log；如需故障诊断，展开 **「高级功能→Debug Log」** 查看日志。
- Motion Control、自定义事件提示音、Mac/Win 触控板方向校准、Debug Log 均归入统一的「高级功能」折叠区域。
- 仅保留必要的设备配对、接收授权、音乐库、播放器和通知。通知会在数秒后自动消失。
